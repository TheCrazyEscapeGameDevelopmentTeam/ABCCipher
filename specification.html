1. 概要

ABC Cipherは、文章やファイルを暗号化・復号するための Webアプリケーションです。

暗号化にはAES-256-GCMを採用しています。 また、文章の暗号文は独自のABCエンコード方式によって、 a・b・cの3種類の文字だけで表現されます。

主な機能

  • 256ビットの暗号鍵の生成
  • 暗号鍵ファイル（.abckey）の保存・読み込み
  • 文章の暗号化・復号
  • ファイルの暗号化・復号
  • 大容量ファイルに対応した分割暗号化
  • 処理の進行状況の表示
  • 暗号化・復号処理のキャンセル

設計上の特徴

文章の暗号文にはABCエンコードを使用し、 ファイルにはバイナリ形式の独自データ構造を使用します。

ファイル暗号化ではデータを1MiB単位に分割し、 各チャンクを個別に認証付き暗号化します。 これにより、ファイル全体を一度に暗号化する方式とは異なり、 分割単位で処理を進めることができます。

3. 動作環境

必要な機能

  • JavaScriptが利用できること
  • Web Crypto APIが利用できること
  • File APIが利用できること
  • Blobによるファイル出力に対応していること

セキュアコンテキスト

ABC CipherはWeb Crypto APIを使用します。 このAPIを利用するため、HTTPSまたはlocalhostでの実行を推奨します。

ファイル保存方式

利用環境が対応している場合は、 File System Access APIの showSaveFilePickerを使用して、 保存先を指定しながらファイルを書き込みます。

この機能が利用できない場合は、Blobを作成して ダウンロードする方式に切り替わります。

4. 暗号鍵の仕様

4.1 鍵の生成

暗号鍵はWeb Crypto APIの crypto.getRandomValues()を使用して生成します。

生成される鍵は32バイト、すなわち256ビットです。 これはAES-256-GCMで使用する鍵の長さです。

4.2 鍵の内部表現

鍵はBase64URL形式に変換して扱います。 Base64URLは、通常のBase64で使われる一部の記号を URLで扱いやすい文字に置き換えた形式です。

4.3 鍵ファイル

鍵ファイルの拡張子は .abckey です。 ファイルの内容は次の形式です。 

ABC Cipher Key File
Version: 2
Key: ＜Base64URL形式の暗号鍵＞

鍵ファイルには暗号鍵がそのまま記録されます。 鍵ファイル自体は暗号化されていません。

4.4 鍵の取り扱い

  • 暗号化と復号には同じ鍵を使用します。
  • 鍵を紛失すると、暗号化したデータを復号できなくなります。
  • 鍵ファイルを第三者に渡すと、暗号文を復号される可能性があります。

5. ABCエンコード方式

5.1 概要

ABCエンコードは、バイト列をa・b・cの3種類の文字だけで 表現するための方式です。

この方式では、各バイトを3進数として表現し、 6桁にそろえて文字列に変換します。

5.2 変換規則

3進数の数字 対応する文字
0 a
1 b
2 c

1バイトは0～255の値を持ちます。 3進数6桁では最大729通りの値を表現できるため、 1バイトの値をすべて表現できます。

5.3 データ長

1バイトにつき6文字を使用します。 したがって、変換後の文字列の長さは 元のバイト数の6倍になります。

例えば、元データが10バイトなら、 ABCエンコード後は60文字になります。

5.4 復号時の検証

ABCエンコードされた文字列をバイト列に戻す際には、 次の条件を確認します。

  • 使用されている文字がa・b・cのみであること
  • 文字列の長さが6の倍数であること
  • 各6文字を数値に変換した結果が255以下であること

ABCエンコードは暗号化方式ではありません。 データをa・b・cだけで表現するための符号化方式です。 データの機密性はAES-256-GCMによって確保します。

6. 文章の暗号化方式

6.1 処理の流れ

  1. 入力された文章をUTF-8形式のバイト列に変換する。
  2. 12バイトのランダムなIVを生成する。
  3. AES-256-GCMで暗号化する。
  4. 暗号化結果にヘッダー情報を付加する。
  5. 全体をABCエンコードする。

6.2 暗号化アルゴリズム

項目 値
アルゴリズム AES-GCM
鍵長 256ビット
IV長 12バイト
認証タグ長 128ビット
追加認証データ ASCII文字列 ABCD

6.3 データ構造

現行の文章暗号文は、暗号化されたデータに ヘッダー情報を付加した構造です。

順序 データ 長さ
1 マジック値（ABCD） 4バイト
2 バージョン番号（1） 1バイト
3 IV 12バイト
4 暗号文と認証タグ 可変長

6.4 マジック値とバージョン

マジック値は ABCD です。 データがABC Cipherの現行形式であることを識別するために使用します。

その直後の1バイトはバージョン番号です。 現行の文章暗号文ではバージョン番号1を使用します。

6.5 追加認証データ（AAD）

文章の暗号化では、マジック値 ABCD を AES-GCMの追加認証データ（AAD）として指定します。

AADは暗号化されませんが、認証の対象になります。 そのため、AADが異なる場合は正しく認証されません。

6.6 暗号文の長さ

AES-GCMでは、暗号文の長さは元の平文と同じ長さになり、 さらに16バイトの認証タグが付加されます。

文章暗号文のバイナリデータ全体の長さは、 次のようになります。 

4 + 1 + 12 + 平文のバイト数 + 16

このバイナリデータをABCエンコードするため、 最終的な文字列の長さは上記の6倍になります。

7. 文章の復号方式

7.1 処理の流れ

  1. 入力された暗号文を検証する。
  2. ABCエンコードを解除してバイト列に戻す。
  3. マジック値とバージョン番号を確認する。
  4. IVと暗号文を取り出す。
  5. AES-256-GCMで認証・復号する。
  6. 復号したバイト列をUTF-8形式の文章に変換する。

7.2 認証と復号

AES-GCMでは、復号時に認証タグの検証が行われます。 暗号文や認証に関係するデータが変更されていた場合、 認証に失敗し、復号結果は得られません。

7.3 対応する文章形式

現行形式のほか、旧形式の文章暗号文にも対応しています。 詳細は「11. 互換性」で説明します。
